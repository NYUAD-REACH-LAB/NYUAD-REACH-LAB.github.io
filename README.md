# REACH Lab website

Source and built pages of the public website of **REACH Lab — Robot Learning and Control Lab**,
New York University Abu Dhabi: https://nyuad-reach-lab.github.io

A static site, generated by one Python standard-library script from JSON data files. The built HTML
is committed at the repository root and served as-is by GitHub Pages (`.nojekyll`). The look, the
palette, the artwork and the tone are specified in [`DESIGN.md`](DESIGN.md).

## Deploy facts

| | |
|---|---|
| Repository | `NYUAD-REACH-LAB/NYUAD-REACH-LAB.github.io` |

| First push | by Fares's git-setup prompt |

Every link and asset path is relative (none starts with `/`), so the same files work under a
sub-path or on a custom domain.

## Folder

```
build.py                 the generator and its leak test
data/                    all content (schema below)
src/templates/           page templates ({{name}} escaped, {{{name}}} raw)
src/assets/              site.css, site.js — copied to assets/
src/brand/               the logo of record, copied from the lab's brand folder
src/brand/web/           web derivatives: logo.png, logo-dark.png, favicon-32.png, apple-touch-icon.png
src/photos/              member photos, <id>.jpg, 384 px square — copied to assets/photo-<id>.jpg; a member without one gets the monogram
DESIGN.md                design system
index.html, 404.html     built pages  ┐
research/ people/ …      built pages  ├ written by build.py — never edit by hand
assets/                  built assets ┘
.nojekyll                serve files as-is
```

Built output (`index.html`, `404.html`, `assets/`, `research/`, `people/`, `publications/`, `news/`,
`join/`, `resources/`, `teaching/`, `contact/`) belongs to `build.py`: it deletes and rewrites these
on every build.

## Build

The site lives inside the lab's records folder (`REACH-Lab/reachLab-website/`), and the leak test
reads the records next to it. From this folder:

```sh
python3 build.py --test     # build into a temporary directory, run the leak test, keep nothing
python3 build.py            # build, run the leak test, and on success write the pages here
python3 build.py --records /path/to/REACH-Lab   # if the records are not the parent folder
```

Both commands exit 1 and list every hit if the test fails. The real build then **deletes the built
pages in this folder** as well, so a page that no longer passes can never be committed. Exit 2 means
the records were not found.

The build also warns (without failing) when `data/publications.csl.json` differs from the personal
site's copy, or `src/brand/` differs from the lab's brand folder: re-sync them.

## Preview locally

```sh
python3 -m http.server 8000     # from this folder
```

then open http://localhost:8000. Opening `index.html` directly from disk also works: every link
points at an explicit `index.html`.

## Pages

Home · Research (index + one page per field at `research/<slug>/`) · People · Publications ·
News · Join · Resources · Teaching · Contact · 404. A page with no content is not built and does
not appear in the navigation (Teaching, until `data/teaching.json` lists a course).

## Data schema

All files are UTF-8 JSON. Text is plain (escaped on output); no HTML in data.

### `site.json`
| Key | Type | Meaning |
|---|---|---|
| `name`, `full_name`, `title` | string | "REACH Lab", "Robot Learning and Control Lab", both joined |
| `affiliation`, `affiliation_short` | string | institution |
| `address` | list of strings, optional | postal address lines; omitted until a public source gives one |
| `map_url` | string, optional | map link on the contact page (a Google Maps search for the campus); omitted when absent |
| `map_embed_url` | string, optional | Google Maps embed address for the small map window on the contact page; with it absent the page shows only the `map_url` text link |
| `headline`, `mission` | string | home hero |
| `research_intro`, `cross_cutting` | string | research index intro; the cross-cutting sentence |
| `email`, `github` | string | the PI's public email; lab GitHub organisation |
| `pi` | object | `id`, `name`, `role`, `title`, `since`, `website`, `scholar` (Google Scholar URL), `orcid` (ORCID URL), `linkedin` (LinkedIn URL), `bio` (list of paragraph strings); `src/photos/<id>.jpg` is the photo |
| `publications` | object | `from_year` (first year listed), `earlier_work_url`, `withheld_links` (URLs dropped from publication entries) |
| `withheld_fields` | list of numbers | research fields not published |
| `build` | `"all"` or list of page keys | which pages to build (`home`, `research`, `field:<slug>`, `people`, …) |

### `research.json`
`fields`: list of `{number, slug, title, summary, body, art_label}`. `number` 1–7 matches the PI's
field numbering; `slug` is the URL segment and selects the artwork function in `build.py`
(`FIELD_ART`); `summary` is the one-line public phrasing; `art_label` is the artwork's alt text.

### `people.json`
- `groups`: `{key, heading, role, one, many}` for `postdoc`, `phd`, `undergrad` — display order.
- `members`: `{id, name, group, since, fields, topic, bio?, links?}` — current members only. `bio` is a list of plain-text paragraphs written by the member. `links` holds the member's own public profiles, any of `scholar`, `orcid`, `linkedin` (full URLs); only those present are shown, in that order, and only ones the member has supplied or that are confirmed from their own pages. `id` is the record
  file name; `since` a year; `fields` field numbers; `topic` one line.
- `alumni`: `{id, name, group, until, since?}` — years only.

### `news.json`
`items`: `{date, kind, text, link?}`. `date` is `YYYY`, `YYYY-MM` or `YYYY-MM-DD` (shown at that
precision); `kind` one of `paper`, `award`, `talk`, `people`, `lab`; `link` is `{label, url}`.

### `join.json`
`heading`, `lede`, `audiences` (`{title, text, links?}`; `links` is a list of `{label, url}` shown on the Join page only), `include_heading`, `include` (list of strings),
`closing` (the words "recent publications" become a link to the publications page).

### `resources.json`
`groups`: `{heading, items: [{name, text}]}` — names and one-line descriptions only.

### `teaching.json`
`lede` and `courses`: `{title, code?, level?, terms?, text?}`.

### `publications.csl.json`
A copy of the personal site's CSL-JSON file (the personal site's copy is the home; re-sync, never
edit here). Items issued in or after `site.json` → `publications.from_year` are listed.

The publications page gives every entry a "Copy BibTeX" button. The BibTeX is written by `build.py`
from the record alone (`display-venue` supplies journal or booktitle, volume, number and pages; DOI and
arXiv links supply `doi` and `eprint`); a field the record does not hold is left out, never guessed.
Authors are "Given Family" with a one-word family, except those listed in `BIB_FAMILY` in `build.py`.

### `conference-addresses.json`
`{"<booktitle>": {"<year>": "City, Country"}}`: the BibTeX `address` of each conference, looked up by the
booktitle as `build.py` writes it and the paper's year. Taken from the conferences' own sites; a conference
paper with no entry gets no `address` and the build prints a warning.

### `bibtex-details.json`
`{"<publication id>": {"volume"?, "number"?, "pages"?, "publisher"?, "editor"?}}`: BibTeX fields the CSL record does not
carry (`publisher` and `editor` are used for conference papers only). Read from Crossref (OpenAlex where Crossref was unavailable) by DOI; they override what the build
reads from `display-venue`. Articles that Elsevier numbers by article number carry it as `pages`. A paper
with no DOI (the two ICRA 2026 papers) has no entry. The personal site keeps a byte-identical copy of this file and of
`conference-addresses.json` in `personal-website/data/`; copy both there after editing.

### `publication-fields.json`
`{"<publication id>": [field numbers]}`. Every listed publication must have an entry (an empty list
is allowed); the build stops if one is missing.

## Leak test

`build.py` refuses to publish a page that contains anything it should not. It reads the private
records to learn the forbidden strings, so nothing private is written in this repository. It checks
every built `.html`, `.css` and `.js` file for:

- strings taken from the records: proposal titles, ids, sponsors and aliases; names and ids of people
  who did not join; every `evidence:` entry (matched as whole words, case-insensitive);
- email addresses other than the PI's public one, internal record ids, record folder paths, dollar
  amounts, and a fixed list of words (see `WORDS` in `build.py`);
- structure: a title, a meta description and exactly one h1 on every page; alt text on every image
  and a label or `aria-hidden` on every SVG; every internal link resolves; no path starts with `/`;
  no page over 300 KB with its CSS and JavaScript;
- consistency: every current member is an active record, every alumnus an alumni or departed record.

Two documented allowances: internal links that resolve to a built page are exempt from the folder-path
pattern (the site's own `research/` and `people/` sections), and the exact phrase `decision-making`
(any case) is exempt from the word list — the public name of research field 6, approved 2026-09-13;
the bare word stays forbidden. Do not add allowances to make a sentence pass: rewrite or omit the
sentence.

## Brand assets

`src/brand/logo-nyuad-B-violet-oasis.png` and `…-dark.png` are copies of the logo of record. The
files in `src/brand/web/` were derived from them once (Pillow, Lanczos): the logos scaled to 144 px
tall, and the favicon made by keeping only the arm's Oasis-coloured pixels, centring the whole arm
on a transparent square and scaling it to 32 and 180 px. If the logo changes, re-copy both files and
regenerate the four derivatives the same way; `build.py` only copies them.

## Updating

Content changes are made in `data/`, then `python3 build.py`, then commit and push to `main`. The
weekly update routine (`site-sync`), its prompt and the rules for what may be published live with
the lab's records (`playbooks/website.md` in the records folder).

## Known limits

- **404 at nested addresses.** GitHub Pages serves `404.html` at whatever address was requested. Its
  relative links and stylesheet resolve correctly for a missing top-level address (`/foo`); for a
  missing address inside a folder (`/people/foo`) the page appears unstyled and its links break. Fixing it needs an absolute path,
  which the site deliberately avoids.
- **Links to repositories in the lab's GitHub organisation** match the leak test's folder-path
  pattern (`…-LAB/…`) and are withheld until that rule is settled (`site.json` →
  `publications.withheld_links`).
